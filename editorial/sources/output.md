# Output

Файл описывает формат ответа и чистую верстку под админку.

## Rule Sources

Этот файл — операционный контракт вывода. Он описывает, как редакционный черновик превращается в поля `draft.json` и HTML для админки.

Редакционные требования к фактам, источникам, рерайту, заголовкам и фото берутся из профильных файлов. Здесь фиксируются только формат выдачи, поля админки, HTML-контракт, `taxonomy`, `slug`, `excerpt`, `audit`, `options` и ограничения media-интеграции.

## Машинный Output

Если пользователь прислал `source.json` со `schema: "source.v1"`, просит JSON, payload, файл для админки, импорт в админку или создание черновика, используй `draft.json` по `payload.md`.

Если пользователь просит файл, создай и приложи файл с именем из запроса. Для Launchpad это обычно `*_draft.json`, полученный заменой суффикса `_source.json` на `_draft.json`. В чат не выводи содержимое JSON; дай только короткое сообщение о готовности файла. Если файл создать невозможно, возвращай только валидный JSON без markdown, без пояснений и без code fence.

В `draft.json` публикационный HTML должен быть только в `fields.content_html`.

Не вставляй в `fields.content_html`:
- `fact_check_notes`;
- `risk_notes`;
- `editor_todo`;
- `source_links` как служебный список;
- служебные комментарии для журналиста;
- предупреждения о неполном источнике;
- изображения из внешнего источника, пока media-интеграция отключена.

Все служебное должно быть в `audit`.

## Draft.json Fields

- `target.section` — классифицированный раздел из `taxonomy.md`, если агент уверен.
- `target.categories` — exact-matched suggested WordPress categories из allowed list выбранного section.
- `fields.title` — основной заголовок.
- `fields.slug` — человекочитаемый slug для WordPress permalink: сначала короткая суть новости на русском, затем транслитерация в латиницу; не английский перевод. Lowercase, дефисы вместо пробелов, без спецсимволов. Русская смысловая фраза до замены пробелов на дефисы — до 34 символов; итоговый slug тоже должен быть коротким и понятным.
- `fields.rotation_titles` — до 3 альтернативных заголовков.
- `fields.seo_title` — SEO-заголовок, если уместно.
- `fields.lead` — короткий лид без HTML.
- `fields.content_html` — HTML тела материала.
- `fields.excerpt` — цитата/выжимка для поля “Цитата”, около 400 символов, без HTML. Не обрезай предложение механически.
- `fields.tags` — 3–7 коротких suggested tags с большой буквы, без хэштегов и дублей. Project предлагает теги, importer должен сверять их с существующими метками админки.
- `options` — явные boolean-настройки записи для checkbox fields.

`fields.lead` и `fields.excerpt` могут быть похожими по смыслу, но не должны механически дублировать друг друга. `lead` открывает материал, `excerpt` помогает заполнить поле цитаты/анонса и должен быть самостоятельным редакторским текстом около 400 символов.


## Categories And Taxonomy

`target.section` и `target.categories` заполняются по `taxonomy.md`.

Launchpad importer должен:
- применять только categories, которые exact-match существуют в текущей админке выбранного section;
- не создавать новые WordPress categories;
- показывать warning/notice автору, если category из payload не найдена или не принадлежит выбранному section;
- не выбирать рубрики самостоятельно на стороне importer.

Если `target.categories` пустой, importer не должен молча считать это успехом: автор должен увидеть, что рубрику нужно проверить, если это указано в `audit.editor_todo`.

## Tags

`fields.tags` — предложения для меток. Пиши каждый тег с большой буквы. Для составных русских тегов используй естественную капитализацию: `Искусственный интеллект`, а не `Искусственный Интеллект`.

Не создавай слишком узкие одноразовые теги. Если тег неочевиден, не выдумывай его.

Importer должен обрабатывать `fields.tags` как suggestions: применять существующие метки, а отсутствующие показывать автору/редактору, не создавая их автоматически. Missing/uncertain tags должны попадать в авторскую проверку, а не молча игнорироваться.


## Options

`options` мапится на управляемые checkbox/post option fields в админке.

Importer должен:
- применять только известные stable payload field names из `options`;
- использовать defaults из `payload.md`, если поле отсутствует в старом payload;
- показывать warning/notice, если option не удалось применить;
- не включать комментарии вне разрешенных разделов из `payload.md`;
- не включать промо, избранное, выделение, livecast или спецрежимы без явного значения `true` в payload.

## Базовый текстовый пакет под админку

Если пользователь просит обычный текстовый пакет, а не JSON, возвращай:

```text
title:
slug:
seo_title:
rotation_titles:
1.
2.
3.

lead:

content_html:

quote:

tags:

options:

thumbnail:

photo_notes:

source_links:

fact_check_notes:

risk_notes:

editor_todo:
```

Если поле не применимо, пиши `не нужно` или `нет данных`, а не выдумывай содержание.

## Лид и more

После первого содержательного абзаца/лида в `content_html` ставь:

```html
<!--more-->
```

`<!--more-->` должен идти после первого содержательного блока/лида, а не в начале и не в конце.

Не добавляй `end-tag`, `<!--end-tag-->` и любые устаревшие служебные маркеры.

## Чистый HTML

Генерируй простой HTML.

Допустимые базовые конструкции:

```html
<p>...</p>
<strong>...</strong>
<em>...</em>
<blockquote>...</blockquote>
<h2>...</h2>
<h3>...</h3>
<ul>
<li>...</li>
</ul>
<ol>
<li>...</li>
</ol>
```

Изображения пока не вставляй в `content_html`, если пользователь явно не просит и если media-интеграция не подготовлена. Когда изображения разрешены, используй только чистый контракт:

```html
<img class="aligncenter" src="..." alt="..." />
<dl class="wp-caption aligncenter"><dt><img src="..." alt="..." /></dt><dd>Подпись</dd></dl>
```

Не генерируй:
- декоративные `div`;
- `section`;
- произвольные `span`;
- `id`;
- `dir`;
- произвольные inline-style;
- обертки вокруг изображений;
- неподдерживаемые embed-скрипты;
- лишние пустые абзацы;
- `<b>` и `<i>` вместо `<strong>` и `<em>`.

## Quotes In HTML

Прямые цитаты в `fields.content_html` оформляй курсивом через `<em>`. Выделяй только цитируемую речь вместе с кавычками, а не весь абзац и не авторскую атрибуцию.

Правильно:

```html
<p>Спортсменка опубликовала в соцсетях несколько фото с ювелирными изделиями. <em>«Эти вещи напоминают мне, что уверенность кроется в деталях, и мне не терпится надеть их на Уимблдон»,</em> — написала Соболенко.</p>
```

Неправильно:

```html
<p>Спортсменка опубликовала в соцсетях несколько фото с ювелирными изделиями. «Эти вещи напоминают мне, что уверенность кроется в деталях, и мне не терпится надеть их на Уимблдон», — написала Соболенко.</p>
```

Не используй `<i>`. Не оформляй курсивом пересказ, выжимку или `fields.excerpt`, если это не прямая цитата в `content_html`.

## Source Attribution

В `fields.content_html` источник должен быть атрибутирован, но без механических и прозрачных повторов. Если новость основана на одном внешнем материале, назови источник один раз в первом смысловом абзаце, но не начинай абзац с источника без необходимости. Первый абзац должен начинаться с главного факта; атрибуцию источника ставь ближе к концу абзаца, обычно в последнем предложении. Для коротких заметок до 5 абзацев это жесткий лимит: после первого абзаца не добавляй повторные формулы атрибуции, если нет нового проверяемого источника, прямой цитаты, спорного утверждения, юридического риска, официального заявления или сравнения позиций.

Если во входе есть `source.canonical_url` или `source.url`, первая атрибуция должна содержать ссылку. Используй `source.canonical_url`, если оно есть, иначе `source.url`. Если URL ведет на конкретную запись/материал источника, ставь ссылку только на глагол атрибуции в короткой финальной фразе первого абзаца: `Об этом Times.by <a href="URL" target="_blank">пишет</a>.` Если URL ведет на сам источник, главную страницу, раздел или профиль, ставь ссылку на название источника: `Об этом пишет <a href="URL" target="_blank">Times.by</a>.` Не выдумывай ссылку, не ставь ссылку одновременно на название и глагол, не растягивай ссылку на всю вводную фразу. Если URL во входе отсутствует, оставь первое упоминание источника без ссылки и добавь задачу в `audit.editor_todo`: `Добавить ссылку на источник.`

Не ставь вводную конструкцию `источник пишет/сообщает` в конец того же предложения. Плохо: `Арина Соболенко показала украшения..., Times.by <a href="URL" target="_blank">пишет</a>.` Хорошо: `Арина Соболенко показала украшения... Об этом Times.by <a href="URL" target="_blank">пишет</a>.` Если ссылка на глаголе нужна, раздели первый абзац на главное новостное предложение и короткую атрибуцию.

После первого упоминания подавай обычные уточняющие факты напрямую. Не добавляй формулы “по данным источника”, “по данным издания”, “как пишет источник”, “источник отмечает”, “там уточняют”, “в материале говорится”, “в исходном материале говорится”, “в публикации говорится”, “в статье говорится”, “издание также сообщает”, “источник также приводит” в последующих смысловых блоках.

Не используй размытую вторичную атрибуцию без конкретного первоисточника: “со ссылкой на СМИ”, “по данным СМИ”, “как пишут СМИ”, “со ссылкой на источники”, “сообщают источники”, “пишут телеграм-каналы” без названия. Если входной источник опирается на неназванные СМИ/источники, не переноси эту формулу в `content_html`; добавь практическое предупреждение в `audit.fact_check_notes` или `audit.editor_todo`.

Не искажай происхождение информации. В `fields.content_html` нельзя писать, что человек `рассказал`, `заявил`, `сообщил` или `признался` конкретному сайту, если во входе нет явного интервью, прямого комментария или официального обращения этому сайту. Вторичный источник может `писать`, `сообщать`, `приводить слова`, но не становится адресатом высказывания без подтверждения.

Не описывай структуру исходного материала в `fields.content_html`. Запрещены все мета-формулы вида “в исходном материале также говорится”, “в материале говорится”, “в публикации говорится”, “в статье также говорится”, “в конце материала”, “далее издание пишет”, “автор материала отмечает”. Публикационный текст должен подавать факты напрямую, а не пересказывать ход чужой статьи.


## Verified Context

Не добавляй в `fields.content_html` фоновые сведения из памяти модели. Дополнительный контекст допустим только из входных проверяемых источников: `source.links`, `editor.notes`, приложенных материалов или явно переданных URL/документов. Если дополнительный факт используется в тексте, его источник должен быть отражен в `audit.source_links`.

Если контекст кажется полезным, но во входе нет проверяемого источника, не вставляй его в публикационный текст. Добавь короткую задачу в `audit.editor_todo`.

Если в черновике появляется такая формула, это ошибка поля `fields.content_html`: убери ссылку на структуру источника и оставь сам факт, либо перенеси сомнение в `audit`.

## Letter Yo

Не используй букву `ё` в генерируемых полях `draft.v1`: `fields.title`, `fields.rotation_titles`, `fields.seo_title`, `fields.lead`, `fields.content_html`, `fields.excerpt`, `fields.tags` и `audit`. Заменяй ее на `е`, кроме дословных цитат и официальных имен, где изменение может исказить написание.

## Ссылки

Внешние и внутренние ссылки оформляй обычным `<a href="..." target="_blank">...</a>`, если ссылка нужна в тексте.

Не превращай каждое упоминание в ссылку. Ссылка нужна там, где она подтверждает источник, документ, пост или важный контекст.

## Embed

Если нужен embed, используй поддерживаемые shortcode-форматы, а не сырой script-код.

Поддерживаемые типы:

```text
[instagram]...[/instagram]
[threads]...[/threads]
[tiktok]...[/tiktok]
[tweet]...[/tweet]
[telegram]...[/telegram]
[video]...[/video]
```

Если пользователь дал только ссылку, не вставляй сырой embed. Верни ссылку и пометку, какой shortcode нужен.

## Таблицы

Если таблица нужна, делай простую таблицу без декоративных стилей:

```html
<table border="1" cellspacing="0" cellpadding="2">
<thead>...</thead>
<tbody>...</tbody>
</table>
```

Используй таблицы только если они реально улучшают восприятие.

## Цитата для админки

`fields.excerpt` должен быть пригодным для поля “Цитата”: около 400 символов, самостоятельный, понятный автору и без механически оборванного предложения. Не выдумывай прямую речь. Можно предложить редакционную выжимку, но не оформляй ее как цитату конкретного человека, если это не прямая речь из источника.

Не переносите в `fields.excerpt` служебную атрибуцию источника. Запрещены формулы вроде “источник сообщает”, “издание пишет”, “в материале говорится”, “по данным источника”, “по данным СМИ”, “со ссылкой на СМИ”. Поле “Цитата” должно звучать как самостоятельная выжимка факта, а не как пересказ чужого материала. Если в исходнике неясен первоисточник, это должно попасть в `audit.fact_check_notes` или `audit.editor_todo`, а не в `fields.excerpt`.

## Footer

Не сочиняй служебный футер, если пользователь не просит. Если нужен footer, укажи тип:

```text
footer: news
footer: article
```

Для news обычно достаточно блока с телеграм-ботом. Для article может потребоваться запрет на перепечатку. Не вставляй служебный footer без необходимости.
