**Проект:** Onliner  
**Дата фиксации:** 2026-10-27 (Europe/Warsaw)  
**Статус:** справочный документ; **не является инструкцией на выполнение изменений**  
**Основание:** исследовательский отчёт Codex `.chatgpt/codex-chatgpt-20261027-121936.md` (состояние репозитория на момент аудита).

## 1. Назначение и границы

Документ сохраняет карту существующих агентских инструкций, скилов и автоматизаций, принятые подходы и отложенные вопросы. Он не заменяет `AGENTS.md`, `SKILL.md`, документацию Tasks или исполняемые скрипты. Перед будущими изменениями Codex должен сопоставлять этот исторический срез с актуальными файлами репозитория.

**Сейчас ничего не реорганизуем:** не создаём скилы, не меняем инструкции, Tasks, PowerShell или Stream Deck. Все предложения ниже — backlog, а не одобренные патчи.

## 3. Принятые принципы

1. **Постоянные обязательные правила** оставлять в соответствующем `AGENTS.md`, не дублируя их в скилах.
2. **Скил** нужен лишь для самостоятельной повторяемой процедуры с реальным сценарием применения и достаточной методикой; название само по себе не причина его создавать.
3. **Исполняемые действия** (передача, проверка, распаковка и перенос файлов) должны выполняться скриптами или Tasks, а не имитироваться текстовыми инструкциями.
4. **Единый источник истины** для правил и исполняемой логики. Не поддерживать вручную несколько конкурирующих копий.
5. **Универсальные соглашения** отделять от путей, ограничений и специализированных процедур Onliner.
6. **Исследование прежде реализации:** карта механизма, фактическая точка входа, зависимости, риски, затем минимальный согласованный патч.
7. Codex собирает репозиторные факты и выполняет согласованные изменения; архитектурное решение принимается после ревью.

### Codex Collaboration

- ChatGPT создаёт `chatgpt-codex-yyyymmdd-hhmmss.md`.
- Codex отвечает `codex-chatgpt-yyyymmdd-hhmmss.md` с **тем же timestamp**.
- Время — локальное, обязательны секунды.
- Codex работает с актуальными файлами репозитория; ChatGPT проверяет результат.
- ZIP-патчи не создаются без отдельного запроса.
- **Решение:** универсальный `Codex Collaboration` skill сейчас **не создавать**; контракт уже закреплён в `AGENTS.md`. Вопрос о глобализации соглашения можно пересмотреть при доказанной межпроектной потребности.

### Stream Deck — решения 2026-10-27

- **Обе кнопки сохраняются:** передача Markdown в Codex и применение ZIP-патчей реально используются.
- **Markdown-кнопка** должна выбирать **последний подходящий** файл автоматически, без запроса имени пользователем. Как именно детерминировать равные timestamps и проверять кандидата — вопрос будущего патча.
- **ZIP-кнопка** должна сохранять возможность заменять существующие файлы проекта: полный запрет overwrite несовместим с её назначением. Проверки происхождения, структуры и целевых путей нужно определить перед изменением скрипта.
- Направление на будущее: один отслеживаемый в Git скрипт как источник истины, Stream Deck только запускает его. **Перенаправление кнопок пока не одобрено к выполнению.**

## 4. Проблемы и риски, подтверждённые аудитом

| Область | Наблюдение | Что это означает |
| --- | --- | --- |
| Документация | `docs/assistant-tasks-workflow.md` требует старый handoff/patch ZIP процесс | В новых чатах можно ошибочно восстановить неактуальный сценарий вместо direct-edit Codex |
| Имена артефактов | `.chatgpt/README.md` показывает timestamp без секунд | Конфликт с `AGENTS.md` и реальным именованием |
| VS Code Tasks | Не проверяются containment путей, `..`, absolute paths и коллизии | `handoff` потенциально читает/пишет вне предполагаемой области; использует `-Force` |
| VS Code Tasks | Документирован `includes` с `;`, реализация использует запятые | Ошибка в примерах и ожиданиях оператора |
| Скрипты Stream Deck | Кнопки вызывают внешние копии в `.tools`, а не tracked скрипты | Git-изменение в репозитории не меняет фактически запущенную версию |
| Передача Markdown | Выбор по свежести без строгой валидации; при совпадении назначения возможен молчаливый fallback | Риск переноса неверного файла и неочевидного результата |
| Применение ZIP | Последний произвольный `*.zip` и распаковка с `-Force` | Риск применить неподходящий архив с заменой файлов |
| Proofreading skill | Активная директория была untracked | Риск потери после clone/checkout |
| Telemetry | v0.4 дублирует методику активного скила | Потенциальное расхождение источников истины |
| Другие документы | Version note monthly reference отстаёт; bookmarklet reference требует review | Низкоприоритетная документационная задолженность |

Сведения о безопасности скриптов получены **статическим аудитом** Codex. Скрипты и кнопки в ходе исследования не запускались.

## 5. Backlog без разрешения на реализацию

### Приоритет A — исследовать перед будущим патчем

1. **Контракт ZIP-патчей.** Проверить несколько реально используемых архивов, определить допустимую структуру, файлы/пути и поведение при ошибке. Сохранить контролируемую замену файлов, не вводить непроверенный обязательный manifest. Отдельно оценить риск частичного применения при сбое.
2. **Markdown transfer.** Сохранить выбор последнего подходящего файла; согласовать строгую маску имени, сортировку при совпадении времени, корректную обработку коллизий и ошибок без ложного сигнала об успехе.
3. **Stream Deck script ownership.** Проверить, как безопасно направить обе кнопки на канонические repo scripts, не нарушив существующие действия.
4. **VS Code Tasks path safety.** Проверить минимальный локальный hardening `assistant: request block`. Вынос длинной inline-реализации в `.ps1` — только при доказанной пользе, не самоцель.

### Приоритет B — согласовать документацию и Git-состояние

5. Исправить или явно пометить legacy-процесс в `docs/assistant-tasks-workflow.md`.
6. Привести timestamp в `.chatgpt/README.md` к формату с секундами.
7. Уточнить статус `onliner-proofreading-analysis/SKILL.md` и архивных копий telemetry без удаления полезной истории.
8. Проверить, сохраняется ли назначение `.responses/`; при необходимости уточнить retention.
9. Позже проверить version note месячного скила и reference bookmarklet.

### Пока не делать

- Не создавать универсальный Codex Collaboration skill.
- Не объединять предметные Onliner skills.
- Не дублировать JS-правила из `docs/JAVASCRIPT.md` в `AGENTS.md`.
- Не изменять месячное архивирование без отдельной причины.
- Не добавлять общий реестр скилов, маршрутизатор или инфраструктурный слой только ради формализации.
- Не менять существующие скрипты и инструкции на основании одного этого документа.

## 6. Неопределённости и условия возобновления

- Реальная структура и соглашение об источнике ZIP-патчей ещё не согласованы.
- Поведение при равном `LastWriteTime`, неполном скачивании или совпадающем имени Markdown требует отдельного решения.
- Следует проверить актуальное Git-состояние каталогов скилов: статус в отчёте — снимок, а не неизменный факт.
- Назначение `.responses/` и актуальность некоторых telemetry-версий не установлены окончательно.

При возобновлении работы **сначала перечитать** `.chatgpt/codex-chatgpt-20261027-121936.md` и сверить выводы с текущими скриптами/конфигурацией. Затем подготовить узкое задание Codex на выбранный пункт. Никакие пункты backlog не означают предварительного разрешения менять файлы.
